# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

A resume site for Alison Rafael Marinho Gonçalves, sourced from his LinkedIn export, plus a v2 backend (auth + Blog) now under active development. Content, audience, and stack decisions were made deliberately — see [`CONTEXT.md`](./CONTEXT.md) for domain vocabulary (including the v1/v2 split) and [`docs/adr/`](./docs/adr/) for architectural decisions before changing scope or infrastructure.

Note: `/home/argmalison/projects/alisonrafael.me` (an earlier Angular/NestJS/Mongo attempt at the same site) exists on disk but is abandoned in favor of this project.

## Repo layout

npm workspaces monorepo — see [ADR 0002](./docs/adr/0002-npm-workspaces-monorepo.md) for why. Three workspaces — `web-client`, `server`, and `shared` (data both apps need, e.g. the Tech Stack list; see [ADR 0008](./docs/adr/0008-shared-workspace-for-cross-app-data.md)) — orchestrated from the root `package.json`. `shared` must be built (`npm run build:shared`) before either consumer, since both import its compiled `dist/`, not raw source.

## Commands

Run from the repo root:

- `npm run dev:web` — Vite dev server for `web-client`
- `npm run dev:api` — NestJS dev server (watch mode) for `server`
- `npm run build:web` / `npm run build:api` — build one workspace
- `npm run build` — build both

Per-workspace commands (`npm run lint`, `npm run preview`, NestJS's `npm run test`/`test:e2e`, etc.) still work via `--workspace=web-client` / `--workspace=server`, or `cd` into the workspace directly.

## Stack

- **`web-client`**: Vite + React 19 + TypeScript + React Router + Tailwind CSS v4 (CSS-first config via `@theme` in `src/index.css`, no `tailwind.config.js`) + Framer Motion.
- **`server`**: NestJS + TypeORM + MariaDB (`mysql2` driver) + JWT auth (`@nestjs/jwt`, `@nestjs/passport`, `passport-jwt`) + `class-validator`/`class-transformer` + `@anthropic-ai/sdk` (trend discovery/draft generation, see [ADR 0007](./docs/adr/0007-anthropic-api-for-trend-discovery.md)). See [ADR 0003](./docs/adr/0003-mariadb-typeorm-backend-datastore.md) for the datastore choice. `server/tsconfig.json` uses `"module": "nodenext"` — every relative import needs an explicit `.js` extension, including in files that don't exist yet.

## Architecture

### `shared/`

- `src/index.ts` — currently just `techStackGroups` (the Tech Stack, see `CONTEXT.md`), canonically owned here. `web-client`'s `en.ts` imports it to render the public Skills section; `server`'s trend-filter agent imports the same array to build its prompt. See [ADR 0008](./docs/adr/0008-shared-workspace-for-cross-app-data.md) for why this exists and what it cost (`web-client`'s Docker build lost its self-contained-context independence — see Deployment below).

### `web-client/`

- `src/content/en.ts` — the single source of truth for all resume copy, typed by `src/content/types.ts` (`ResumeContent`). Content changes are code changes to this file (the Blog, once it has an admin UI, will be the exception — it's server-managed, not code).
- `src/i18n/index.ts` — locale registry (`useResumeContent`). Only `en` exists today; adding a language means adding `src/content/<locale>.ts` and registering it here — no i18n library is used, by design.
- `src/pages/ResumePage.tsx` — the entire resume is one page: `Hero` and `Stats` full-width, then a two-column desktop layout (`Experience` left; a sticky sidebar with `Skills` and `Credentials` right, which stacks below Experience on mobile), then a full-width `Contact` close. Also runs a mount-only effect that finishes scrolling to `location.hash` when arriving here via a full navigation (e.g. Nav's "Experience" link clicked from `/blog`) — a plain `<a href="/#experience">` gets the browser's free native hash-scroll for a same-page click, but a full page load scrolls to the fragment before this page has rendered the target section, so the browser's own attempt silently does nothing without this effect.
- `src/blog/` — the public Blog reading UI (`/blog` card grid, `/blog/:slug` detail), reading `server`'s public `/posts` routes via its own small `src/blog/api.ts` (deliberately separate from `src/admin/api.ts` — no coupling between the public site and the Admin Panel). `App.tsx` imports `BlogRoutes` via `React.lazy`/`Suspense`, same reasoning as `src/admin/` below: `react-markdown` (rendering Post `content`) must not ship in the main resume bundle. The list payload carries `coverImageUrl`, `viewCount`, and an approved `commentCount` per Post so the cards render without follow-up requests. `BlogPostPage` fires `POST /posts/:slug/views` once from its load effect (a per-slug `useRef` guard stops React StrictMode's dev double-invoke from double-counting; see [ADR 0010](./docs/adr/0010-view-counter-intentionally-undeduplicated.md)). `src/blog/components/Comments.tsx` renders the approved comments (one level of replies) and the submit form (name + optional private email + plain-text body, an "awaiting moderation" confirmation on success, a distinct message on a `429`); it copies `formatRelativeTime` from `admin/pages/TrendsPage.tsx` rather than adding a relative-time dependency. Nav's own UI strings (like "Blog") are hardcoded JSX, not added to `content/en.ts` — that file is reserved for the resume's own content, not page chrome (see `src/content/en.ts` below).
- `src/App.tsx` runs everything through React Router (with a `NotFoundPage` catch-all): `/` is the resume, `/blog/*` and `/admin/*` are each lazy-loaded route modules.
- `src/admin/` — the Admin Panel (`/admin/*`, see `CONTEXT.md` and [ADR 0005](./docs/adr/0005-admin-panel-in-web-client.md)). `App.tsx` imports `AdminRoutes` via `React.lazy`/`Suspense` specifically so none of this — including `@uiw/react-md-editor` — ships in the public page's bundle; don't import anything from `src/admin/` outside that lazy boundary. `AuthContext` holds the JWT in `localStorage` (see [ADR 0006](./docs/adr/0006-admin-session-model.md)) and calls `GET /auth/me` on mount to validate it, clearing it on failure. `PendingCommentsContext` (mirrors `AuthContext`, rendered inside it) holds the count of `pending` Comments so `AdminLayout` can show a nav badge and `pages/CommentsPage.tsx` (the moderation UI — status filter, otherwise-hidden `authorEmail`, approve/reject/delete) can refresh it after each action without a navigation. `content/en.ts` + `i18n/index.ts` mirror the public site's `src/content`/`src/i18n` pattern (see below) — the Admin Panel is English-only by design, but its copy still lives in one typed file, not scattered JSX strings.
- `pages/PostEditorPage.tsx` — `@uiw/react-md-editor`'s `preview="live"` gives the split raw-markdown/rendered-preview view; its default toolbar "image" button is swapped via `commandsFilter` (not `extraCommands`) for one that opens a file picker and uploads through `POST /uploads`, and the same upload path is wired to the raw textarea's native `onPaste`/`onDrop` (via `textareaProps`) for drag/paste image insertion — both insert the returned URL at the cursor position. A separate "Cover image" picker (optional, above the editor) uploads through the same `POST /uploads` path and stores the returned URL as the Post's `coverImageUrl`. `data-color-mode="dark"` plus the `[data-color-mode='dark']` CSS variable overrides in `index.css` repaint the editor's default GitHub-dark palette to match this site's theme tokens.
- `.env.production` / `.env.development` — `VITE_API_URL`, read by `src/admin/api.ts`. Committed (not secret, just the API's public hostname) since Vite bakes it in at build time; there's no runtime env injection for this static site.
- `pages/TrendsPage.tsx` — the "Get top trends" flow (see `CONTEXT.md`'s Trend/Trend Search definitions and [ADR 0007](./docs/adr/0007-anthropic-api-for-trend-discovery.md)): on mount, `GET /trends/searches/latest` shows the last saved Trend Search — this never triggers a new Claude call. `POST /trends/discover` only runs when the Admin presses "New search"; multi-select checkboxes over the results, `POST /trends/drafts` for the selected ones. Per-item `created`/`failed` results render inline (best-effort batch, not all-or-nothing).
- `src/components/Experience.tsx` — roles are split into `emphasized` (shown open) vs. not (collapsed behind "Show earlier roles"), driven by the `emphasized` flag on each entry in `en.ts` rather than a computed date cutoff — update that flag by hand as roles age. Within the emphasized roles, the first is visually marked `current` (accent glow + badge) and the second `recent` (violet dot) — these are positional (index-based), not content-driven, so reordering `en.ts`'s `experience` array changes which role gets which treatment. An `ExperienceEntry` with `totalDuration` set (e.g. Inatel) renders as a grouped sub-list under one company header instead of flat sibling cards.
- `src/components/Credentials.tsx` — merged Education + Certifications into one card (not separate sections) after design review found separate near-empty cards added chrome without content.
- `src/components/Stats.tsx` — the "years of experience / companies / roles held / certifications" strip under the hero. All four numbers are derived at render time from `en.ts` (date parsing + array lengths), never hand-entered — keep it that way when editing content so the strip can't drift out of sync.
- `src/components/Reveal.tsx` / `src/lib/motion.ts` — shared scroll-reveal wrapper and eased-transition constant used across components; add new animated sections through `Reveal` rather than hand-rolling `motion.div` variants.
- `public/resume.pdf` — the downloadable resume; it's a straight copy of the LinkedIn PDF export, not generated from `en.ts`. Replace this file directly to change the download.

### `server/`

- `src/health/` — `GET /health` for container/deploy healthchecks.
- `src/auth/` — the single Admin account. `AuthService` seeds it from `ADMIN_EMAIL`/`ADMIN_PASSWORD` on first boot only (`OnModuleInit`, skipped if an Admin already exists — those env vars aren't re-applied after that). `POST /auth/login` returns a JWT (`JWT_EXPIRES_IN_SECONDS`, a number of seconds — not a duration string; `@nestjs/jwt`'s `expiresIn` treats a numeric *string* as milliseconds but a numeric *type* as seconds, so this must stay `Number(...)`-converted). `GET /auth/me` and `PATCH /auth/me` (both `JwtAuthGuard`) are self-service only — the authenticated Admin viewing/changing their own password (current-password re-entry required; see `CONTEXT.md`'s Admin definition and [ADR 0006](./docs/adr/0006-admin-session-model.md)) — there's no route to manage any *other* account, by design. `AuthModule` exports `PassportModule` (pre-`.register()`'d with the `'jwt'` strategy) so other modules get `JwtAuthGuard` support by importing `AuthModule` — don't re-register `PassportModule` elsewhere, it won't provide the DI token other modules need.
- `src/blog/` — the Blog. `BlogController` deliberately declares the admin routes (`/posts/admin`, `/posts/admin/:id`, all `@UseGuards(JwtAuthGuard)`) before the public routes (`/posts`, `/posts/:slug`, `POST /posts/:slug/views`) — keep that order, Nest matches routes top-down. `BlogService.update()` sets `publishedAt` when `published` flips to `true` and clears it back to `null` when it flips to `false` (see the Post/Admin definitions in `CONTEXT.md`). The `Post` entity has an optional `coverImageUrl` and a `viewCount` (default 0). `findPublished()` is a QueryBuilder that maps an approved-only `commentCount` onto each Post via `loadRelationCountAndMap`; `registerView()` is an atomic `increment` (see [ADR 0010](./docs/adr/0010-view-counter-intentionally-undeduplicated.md)).
- `src/comments/` — reader Comments on Posts (see `CONTEXT.md` and [ADR 0009](./docs/adr/0009-reader-comments-pre-moderated-pseudonymous-one-level-rate-limited.md)). `CommentsController` is also `@Controller('posts')` (so the public URLs are `/posts/:slug/comments`), admin/literal routes declared before the `:slug`-bearing ones. Public: `GET /posts/:slug/comments` (approved only, one level of replies, `authorEmail` never returned) and `POST /posts/:slug/comments` (creates a `pending` Comment; the only route guarded by `CommentRateLimitGuard`, a small in-process fixed-window limiter — 5/IP/hour, no dependency; see ADR 0009 for why not `@nestjs/throttler`). Admin (`JwtAuthGuard`): `GET /posts/comments/admin[?status=]`, `GET /posts/comments/admin/pending-count`, `PATCH /posts/comments/admin/:id/status`, `DELETE /posts/comments/admin/:id`. `Comment` is the schema's first relational entity — `@ManyToOne` to `Post` and a self-referencing `parent`, both `onDelete: 'CASCADE'`; `authorEmail` is `select: false` so public queries can't leak it. One-level threading is enforced server-side (a reply whose parent already has a parent, or whose parent is on another Post, is rejected).
- `src/uploads/` — Upload images embedded in Post markdown (see `CONTEXT.md`). `POST /uploads` (`JwtAuthGuard`, multer `diskStorage`, images only, 5MB cap) saves into `UPLOADS_DIR` (env-overridable, defaults to `./uploads` relative to `process.cwd()` — that's `/app/uploads` under `server/Dockerfile`'s `WORKDIR`, where `docker-compose.yml` mounts a persistent volume; see [ADR 0004](./docs/adr/0004-local-disk-image-storage.md)) and returns an absolute URL built from the request's own host/protocol — no hardcoded public-URL env var needed. `ServeStaticModule` in `app.module.ts` serves that same directory back out at `/uploads/*`. `main.ts` sets `trust proxy` so `req.protocol` reports `https` correctly behind nginx-proxy; without it, uploaded image URLs would come back as `http://`.
- No admin UI in the API itself — `web-client/src/admin/` (above) is the Admin Panel; `server/` stays UI-agnostic, just JSON + file responses.
- `src/trends/` — the three chained Claude calls behind "Get top trends" (see [ADR 0007](./docs/adr/0007-anthropic-api-for-trend-discovery.md)): `TrendsService.discover()` runs the web-search-backed discovery agent (topic + one-line summary only, deliberately light — see ADR 0007's update) then the Tech-Stack relevance filter, and saves the ranked result as a new `TrendSearch` row (`POST /trends/discover`) — `getLatestSearch()` (`GET /trends/searches/latest`) reads the newest row back with no Claude call at all, which is what `TrendsPage.tsx` calls on mount instead of auto-discovering (see ADR 0007's persistence addendum). `createDrafts()` runs the draft-writer agent once per selected Trend — this is the step with its own `web_search` tool and the only place a full write-up gets generated, bounded by the Admin's selection rather than discovery breadth — and saves each via the existing `BlogService.create()`, best-effort, retrying a slug collision with a numeric suffix rather than failing that item (`POST /trends/drafts`). All three routes are `JwtAuthGuard`-protected like the rest of the admin API; the two `POST`s wrap the service call in a try/catch that rethrows as `BadGatewayException` with Claude's real error message — deliberately not Nest's default opaque 500, since this is a single-admin tool with no one else to hide internals from. Every Claude call's `system` prompt demands a bare JSON response (no prose, no code fences); `extractJson()` in `trends.service.ts` parses that (checking `stop_reason` to give an actionable error if the response was truncated), with a fallback that slices out the first-to-last bracket/brace if the model wraps it in anything else.

## Deployment

Single DigitalOcean droplet (Ubuntu 22.04, domain `alisonrafael.me` already pointed at it), Dockerized. Three services now run behind the shared reverse proxy:

- `web-client/Dockerfile` — multi-stage: builds with Node, serves the static `dist/` via nginx (`web-client/nginx.conf`). Publicly reachable at `alisonrafael.me` / `www.alisonrafael.me`. Build context is the **repo root** (`docker build -f web-client/Dockerfile .`), not `web-client/` — it depends on the `shared/` workspace now, which cost it the self-contained build it used to have (see [ADR 0008](./docs/adr/0008-shared-workspace-for-cross-app-data.md)); the build stage runs `npm run build --workspace=shared` before `--workspace=web-client`.
- `server/Dockerfile` — multi-stage: builds the NestJS app with Node, runs the compiled `dist/main.js`. Build context is the **repo root**, not `server/` (`docker build -f server/Dockerfile .`), because npm workspaces hoist the lockfile and `node_modules` there — and now also because it needs `shared/dist` built and copied into both the build and runtime stages. Publicly reachable at `api.alisonrafael.me`.
- `mariadb` (root `docker-compose.yml`) — not on the `nginx-proxy` network, only on the `internal` one shared with `api`; never publicly reachable.
- `docker-compose.yml` (root) — all three services. `web` and `api` join the external `nginx-proxy` network and set `VIRTUAL_HOST`/`LETSENCRYPT_HOST` for cert/routing auto-discovery; `api` and `mariadb` also share an `internal` network for DB traffic. Reads deploy-time secrets (DB credentials, JWT secret, admin seed) from a `.env` file next to `docker-compose.yml` on the droplet — see root `.env.example` for the shape (distinct from `server/.env.example`, which is for running the API locally without Docker). That `.env` is never hand-edited on the droplet: see below, `deploy.yml` regenerates it from GitHub Actions secrets on every deploy.
- `deploy/proxy/` — the shared `nginx-proxy` + `acme-companion` reverse-proxy stack, deployed **once** on the droplet, independent of any single app's lifecycle. See `deploy/proxy/README.md` and [ADR 0001](./docs/adr/0001-nginx-proxy-acme-companion-for-tls.md) for why this shape was chosen over hand-rolled nginx+certbot or a single-container Caddy setup. `vhost.d/api.alisonrafael.me` bumps `proxy_*_timeout` to 180s there specifically, since the trend-discovery/draft-creation endpoints (chained Claude calls with web search) can run well past nginx-proxy's 60s default — this stack's own README explains why a normal `deploy.yml` push never picks this up automatically.
- `.github/workflows/deploy.yml` — on push to `main`: builds and pushes both images to GHCR, then scp's `docker-compose.yml` to the droplet (the repo itself isn't cloned there, so this is the only way that file stays current), SSHes in to write `.env` from GitHub Actions repo secrets, and runs `docker compose pull && up -d`. Needs these repo secrets configured (Settings → Secrets and variables → Actions) before it can run: `DROPLET_HOST`, `DROPLET_USER`, `DROPLET_SSH_KEY`, `DROPLET_APP_DIR` (existing, from the v1 deploy) plus `DB_ROOT_PASSWORD`, `DB_PASSWORD`, `JWT_SECRET`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `ANTHROPIC_API_KEY`.
- The comment rate limit (`CommentRateLimitGuard`, see [ADR 0009](./docs/adr/0009-reader-comments-pre-moderated-pseudonymous-one-level-rate-limited.md)) is a hardcoded constant in `server/src/comments/` — no new dependency, env var, secret, `docker-compose.yml`, or `deploy.yml` change. If it's ever made configurable, that's when the `.env.example` × 2 / `docker-compose.yml` `api` env block / `deploy.yml` `.env` heredoc / GitHub secret chain all need updating together.
